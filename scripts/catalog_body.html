9 · 字号档位

macOS 五档（字号 / 版心）：.smallText 14px / 612px · .mediumText 16px / 640px · .largeText 18px / 668px · .xlargeText 20px / 692px · .xxlargeText 22px / 720px

每档同时给 --measure，.fontSize 把它当 max-width —— 所以列宽（版心）跟着阅读器的字号设置变：14px 时一行约 43.7 个汉字，22px 时约 32.7 个。字号越大行越短。窗口不足时版心取「视口宽度 − 88px」与档位值的较小者。注意 max-width 在 .fontSize 上而不在 body 上：字号类就加在这个 div 上，只有同元素的 --measure 才能作用到自己的 max-width。

下面七行的字号是它们自己带的类，但版心属于外层那个 .fontSize（预览页是 largeText 档）—— 所以这七行不会各自变宽。要逐档看列宽，改 make_catalog.py 的 text_size_class 重新生成。

注意拼法：app 替换进模板的类名来自 ArticleTextSize.cssClass，它返回的是 xLargeText / xxLargeText（大写 L），而 app 自己的默认样式表和官方主题都写 .xlargeText / .xxlargeText。CSS 类名大小写敏感，两边不一致时两个最大档位就是死的 —— 所以主题把两种拼法都写了。下面七行分别验证。

smallText 14px —— 档位最小的一档。

mediumText 16px —— 默认档位。

largeText 18px —— 预览页当前用的就是这一档（[[text_size_class]]）。

xLargeText 20px —— app 实际替换进来的拼法。

xxLargeText 22px —— app 实际替换进来的拼法，最大档位。

xlargeText 20px —— 官方主题与 app 自带样式表的拼法（主题兼容保留）。

xxlargeText 22px —— 同上。

.fontSize + [[font-size]] — iOS 专用：字号由模板变量注入，不是这五个类

iOS 分支（@supports (-webkit-touch-callout: none)）另外给 .fontSize 加了 4px 20px 28px 的内边距、word-break: break-word、-webkit-hyphens: auto、-webkit-text-size-adjust: none。因为 box-sizing: border-box，那 20px×2 会被算进 max-width，**iOS 的版心比 --measure 小 40px**。这些在 macOS 预览里看不到，只能在真机或 iOS 模拟器确认。[[text_size_class]] 只在 macOS 被替换（app 源码里包在 #if os(macOS)），iOS 用的是 [[font-size]]。

10 · 主题未接管的部分

这一节不是手写的，来自 scripts/check_theme_styles.swift 的实际加载结果：NetNewsWire 会把 core.css 插在主题之前，所以下面这些样式由 NetNewsWire 自己 提供，主题一个字都没写。

10.1 core.css 负责、主题不管（有意留白）

html { scrollbar-gutter: stable } · .articleBody { position: relative }（主题的 .systemMessage 绝对定位就靠它当锚点）

广告与分享垃圾一律 display: none !important：iframe[src*="feedads"] iframe[src*="doubleclick"] a[href*=".ads."] img[src*="feedburner"] .social_items .mcnFollowBlock .x-netnewswire-hide 等约 20 条

表情尺寸：img.emoji img.twemoji .twemoji .twemoji svg .wp-smiley —— 主题的 img { height: auto !important } 与 core 的 img.emoji { height: 1em !important } 同为 !important，靠特异性 core 胜出（下面有一段 emoji 实物与断言）

脚注结构：.newsfoot-footnote-container（定位上下文）· .newsfoot-footnote-popover .footnote-return / .footnoteBackLink / .reversefootnote（隐藏返回链接）· .newsfoot-footnote-popover-inner :first-child/:last-child（收边距）

10.2 core.css 给了结构、主题必须显式推翻的地方（已补齐）

core.css 对脚注是结构 + 造型一起给的：芯片是 border-radius: 1em 的药丸、自带 top: -0.1em 抬升，popover 与内层分别有 0.3em / calc(0.3em - 1px) 圆角。主题早先只接管了颜色、底色与描边，漏了圆角与 sup 的位移复位 —— 于是在一个声明「无圆角」的主题里，脚注芯片是药丸形、popover 描边顺着圆角弯、芯片还被 .articleBody sup 二次抬高。

现在 sup[id^='fn'] 显式复位到 vertical-align: baseline; bottom: 0，三处圆角显式写 border-radius: 0。检查器里有 4 条断言在守：脚注芯片方角、popover 方角、内层方角、以及 sup 复位。

教训归档：接管一个 core.css 已经造型过的元素时，「改色」不等于「接管」 —— 没显式推翻的属性会继续用 core 的值。
